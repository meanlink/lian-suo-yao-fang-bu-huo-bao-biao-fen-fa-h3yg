# 连锁药房补货报表分发

`pharmacy-replenishment` 是惠民药房区域运营团队的补货协作纵切面。盘点员录入门店库存和近 7 日销量，系统计算移动平均、安全库存与建议数量，区域经理审核后安排物流班次，收件员完成回执。

## 业务背景

惠民药房有 18 家门店，当前由门店盘点员把 Excel 发到群里，区域经理手工合并，物流班组在纸面清单上分发。主要问题是门店 SKU 口径不一致、临期药品会被机械补货、审核和收件缺乏闭环留痕。

上下游是门店盘点表 → 本系统补货试算与审核分发 → 区域仓配货和班次收件确认。

## 模块

- 门店库存：按门店、SKU、盘点日形成唯一快照。
- 销量预测：取最近 7 日销量移动平均，计算安全库存和再订货点。
- 补货试算：展示日均、波动、安全库存、建议数量和原因。
- 区域审核：仅已提交或人工改写的建议可以生成审核单，经理批准后才能分发。
- 班次分发：为已批准审核单建立收件班次，收件员确认签收。

## 算法口径

日均销量为最近 7 个有效日销量的算术平均。安全库存为 `max(日均 × 安全天数, 样本标准差 × 1.65)`。再订货点为 `日均 × 供货提前期 + 安全库存`。建议数量向上取整到包装规格，并覆盖提前期和安全天数目标库存减去现有库存的缺口。运行日期固定为 `2026-11-21`，便于验收复现。

当有效期到期或临期且存在可替代品时，建议状态为 `blocked`，禁止送审。区域经理必须填写人工数量和理由，状态变为 `overridden` 后才可送审。

## 角色

- `clerk@huimin.local` 盘点员，负责库存快照、预测和送审。
- `manager@huimin.local` 区域经理，负责人工改写和审核。
- `shift@huimin.local` 班次协调员，负责分发收件确认。

## 服务

frontend / backend / worker / db / redis 共 5 个容器。MySQL 端口为 17759，FastAPI 端口为 19259。


## 扩展业务

- 临期处置按门店和 SKU 取最新在库快照，盘点员记录隔离或退仓，保留审计依据。
- 缺货升级使用原补货预测的再订货点。门店登记缺货，区域经理确认处理结果后关闭。
- 定时报表由区域经理按门店、收件人和小时订阅。后台按上海时间每天生成一次门店快照并发送到站内收件箱，收件人可查看冻结的报表明细。
- 回执对账监测超过 2 小时未签收或缺少发送时间的分发，先登记异常，签收后才能结清。

## 仓配履约

班次协调员在「仓配履约」登记供货凭证、批号和有效期。仓配 SKU 的审核单按近效期优先在区域仓分配库存，预留量决不会超出账存。确认打包并发车后，系统在写分发记录的同一事务内扣减库存。尚未进入仓配管理的 SKU 仍可使用原班次分发。

- **入库批号**以 SKU 和批号为唯一身份，列出收货、预留、可用、过期与召回状态。
- **仓库拣配**可跨多个批号满足一张审核单。缺货时整单不预留，未发车单撤销可释放预留并重新拣配。
- **冷藏交接**按模拟仓规记录测温仪和读数。末次测量越界或过期时禁止打包和发车，可保留失败记录并复测。
- **批号召回**按已分配批号追溯门店。未发车单须撤销，已发车门店须登记与实际发车数量一致的隔离凭证。区域经理确认全部回执后结案。
- **仓库盘差**由盘点员申报、经理复核。库存快照已变更、批号被召回或实盘少于已预留数量时拦截过账。

验收剧本使用门店 `S001` 的 `RX-1001`。18 件较早到期的冷藏批号和 65 件常温批号共同履行 42 件审批单。先登记越界记录再登记合格复测，确认后发车。随后登记冷藏批号召回，门店回执 18 件，经理结案。常温批号账存为 41 件，复盘实点 37 件，经理过账后更新库存。
